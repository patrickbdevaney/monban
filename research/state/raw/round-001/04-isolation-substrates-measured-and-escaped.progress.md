## Batch 6
- USENIX Sec 2025 Yu et al. (HIT) "Exploring and Exploiting the Resource Isolation Attack Surface of WebAssembly Containers" arXiv 2509.11242: Wasmtime 24.0.0 / Wasmer 4.3.2; WASI fs ops (sync, file op, large R/W, /dev) degrade co-tenant host I/O by >93-99% with Wasm-instance CPU only 0.09-10%; fuel doesn't capture it; /dev/urandom rate -92%. => resource isolation (I/O, inodes, fds) is outside Wasm's memory-safety boundary.
- Comparative Wasmtime vs Firecracker (Besozzi et al., VHPC25, arXiv 2509.09400): Wasm lower cold start for light functions, degrades with complexity; Firecracker stable, better I/O-heavy.
- eWAPA arXiv 2409.10252: Wasm3 < Wasmtime startup; WAMR/Wasmer significantly higher (runtime config dependent).
- Landlock: kernel docs list ABI 1..11 (ABI 4 TCP, 6 scopes abstract unix/signals, 8 TSYNC, 10 UDP, 11 NO_NEW_PRIVS). Gaps: chdir/stat/chmod/chown/fcntl not restrictable, 16 layers max.
- eBPF verifier: long LPE CVE history (CVE-2020-8835, CVE-2021-31440, CVE-2021-3600, CVE-2022-23222); unprivileged BPF disabled by distros => eBPF not a tenant-code substrate.

- V8: snapshot deserialization context <2ms; embedded builtins shared; no independent isolate density benchmark found (gap).
## Batch 7
- Crash semantics (wasmtime source traphandlers.rs, main 2026-10): host-function panics caught with catch_unwind (only with panic=unwind) and re-raised to the embedder after unwinding wasm frames; panics in non-catching libcalls => process abort. Component model: reentrance violation traps "cannot enter component instance". => if server built panic=abort, any of the ~15 2026 "guest can panic host" advisories = whole-process DoS.
- KVM: CVE-2026-53359 "Januscape" (oss-sec 2026/q3/64, July 2026, Hyunwoo Kim): UAF in KVM/x86 shadow MMU, guest->host, Intel+AMD, ~16 yrs latent, kvmCTF 0-day, $250k tier; appears to need nested virt exposed; fix 81ccda30b4e8. => microVM TCB includes KVM; disable nested virt.
