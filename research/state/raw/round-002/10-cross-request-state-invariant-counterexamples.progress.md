## Checkpoint 1 (sources 1-7)
Invariant under test (round-001 report l.50): "no cross-request state that unauthenticated input can influence".
- RFC 8446 (2018-08) §4.2.11: "there is no need for the server to associate an SNI value with the ticket"; §4.6.1 SNI-match is client-side SHOULD only; ticket_lifetime max 604800s; §8: server MUST accept same 0-RTT handshake at most once per instance; app-level replay "MUST be dealt with by any application"; §8.3 freshness window ~10s, "billions of replays" possible in window. => spec itself sanctions cross-SNI resumption = authenticated (STEK-MAC'd) state with no SCOPE binding.
- Hebrok et al. USENIX Sec 2025 "STEK Sharing is Not Caring": client-auth bypass via ticket resumption across vhosts in Apache (CVE-2025-23048), nginx (CVE-2025-23419), (Open)LiteSpeed, Caddy; Cloudflare mTLS (fixed by disabling resumption with mTLS); Fastly resumed regardless of SNI (fixed Sept 2023 by binding tickets to issuing cert); DDoS-Guard cluster 10 ASes; scan Dec2024-Jan2025: 59.75M pairs, 176 vulnerable manual. LiteSpeed/Caddy only 1 global STEK. Countermeasure: bind ticket to server cert chain + client cert/trust-store (OpenSSL session id context = hash, set in ClientHello cb on SSL not SSL_CTX). SNI-binding alone insufficient.
- Hebrok et al. USENIX Sec 2023 "We Really Need to Talk About Session Tickets": AWS ALB faulty STEK rotation -> passive decryption >=1.9% Tranco top100k; GnuTLS all-zero STEK (CVE-2020-13777); keystream reuse; resumption ~4% CPU of full handshake.
- Gellert & Handirk ePrint 2021/987: SRAH formal; secure iff client names intended receiver.
- PortSwigger "Gotta cache 'em all" (Doyhenard, 2024-08-08, BH USA 2024): delimiter (Spring ';', Rails '.', OLS %00, nginx %0a) and normalization discrepancies; CloudFront/Azure/Imperva normalize before cache rules, Cloudflare/GCP/Fastly don't; defense Cache-Control no-store,private; don't let cache rules override.
- draft-rajappa-httpbis-connection-contamination (fetch failed 404 at mirror; search summary only): routing decided at connection setup not per request -> cross-tenant on coalesced conns.
VERDICT so far: invariant as stated is FALSE as a sufficient condition: tickets are authenticated (MAC'd) yet cross-scope. Refinement: state must be bound to (issuer, scope/principal, authority-context) and re-validated at use against CURRENT policy.
