## Decision logic (oracles/cred-select table)

| row | where |
|---|---|
| R0 | `select(raw)`: `aegis_wire::tls_peek::client_hello` refused → `None`. A sigalgs body that is not whole u16s, or a trust_anchors body that is not exact `opaque<1..32>` entries, is also `None` (defence in depth; the peek already refuses both). |
| E0 (SEL-3) | `CredentialSelector::new` keeps only `listener == L`: another listener's credential is never held. |
| E1, E2 (SEL-2) | `Profile::sigalgs()` (F12) contains the scheme; kind mldsa never on P-PUBLIC-WEB. Applied at construction and again per hello. |
| E3 | scheme in the peeked `signature_algorithms` (absent = empty). |
| E4 (SEL-1) | mtc: its TrustAnchorID byte-equal to an entry of the peeked `trust_anchors` (0xCA34, the peek's codepoint). |
| R1..R4 | `CredentialKind::TIERS = [Mtc, MlDsa, X509]`, first eligible in configured order; none → `None`. |

rustls wiring: `config_for(raw)` clones the listener's `ServerConfig` (built once in `new` by `server_config_with`,
so the startup assertions ran) and installs `ProfileCertResolver::wrap(BoundSelector)`. `BoundSelector::resolve`
serves the peek's choice only if rustls's offered schemes are a subset of the peeked list and contain the chosen
scheme (rustls filters the client's list by suite compatibility, so a subset, never a superset); otherwise nothing,
and rustls fails the handshake.

## API for P7-bin-001

```rust
use aegis_tls::{Credential, CredentialKind, CredentialSelector, SelectError, key_scheme, BoundSelector};

CredentialKind::{X509, MlDsa, Mtc}; CredentialKind::from_name("x509"|"mldsa"|"mtc"); kind.name()
key_scheme(&CertifiedKey) -> Option<SignatureScheme>          // the one TLS 1.3 scheme the key signs with (None for RSA / none)
Credential::new(id, listener, kind, scheme: SignatureScheme,
                trust_anchor_id: Option<Vec<u8>>,              // aegis-config TrustAnchorId::wire(); Some iff mtc; 1..=32 B
                key: Arc<CertifiedKey>) -> Result<Credential, SelectError>
    // refuses: empty id; ta on non-mtc / missing on mtc; mldsa with a non-ML-DSA scheme; key not signing `scheme`;
    // x509/mldsa whose chain's end-entity SPKI is not the key (keys_match). The mtc chain is opaque (not parsed).
CredentialSelector::new(profile: Profile, listener: &str, pool: impl IntoIterator<Item = Credential>)
    -> Result<CredentialSelector, SelectError>                 // SelectError::Profile for a pending profile
selector.set_alpn(Vec<Vec<u8>>)
selector.select(raw: &[u8]) -> Option<&Credential>              // None = handshake_failure
selector.select_peek(&Peek) -> Option<&Credential>
selector.bind(raw) -> BoundSelector                            // impl ResolvesServerCert
selector.config_for(raw: &[u8]) -> Arc<ServerConfig>           // per connection; feed rustls the same raw bytes
selector.credentials() / profile() / listener()
```

Suggested boot path: for each non-L4 listener, `TlsBlock::candidates(cfg, name)` → load chain/key → `key_scheme` →
`Credential::new(c.id(), name, kind, scheme, c.trust_anchor_id().map(|t| t.wire()), ck)` → `CredentialSelector::new`.
Per connection: read the first record (the same peek as D-P7.2, with the stall deadline), `config_for(&buf)`, then
`ServerConnection::new` (or `Acceptor` + `Accepted::into_connection`) and feed it `buf`. Exit 78 if `tls` is
configured without feature `mtc`.
