# P6-tls-001 report (implementer, 2026-11-04, rebased on main bff02b6)

## Built
- **aegis-tls `profile.rs`**
  - `Universal`, `BsiAlt` and `Cnsa` are now `Active`, so `server_config` and `client_config` build them. The
    `PENDING_11ED/BSI/CNSA` strings are removed. Only `FipsCmvp` is still Pending: it needs the cmvp build.
  - P-PUBLIC-WEB is now `[0x11EC, 0x11ED, 0x11EB, 0x001D, 0x0017]`, matching F12 `kx_groups`.
  - `f8_name(FipsPqRequired)` is now `Some("FIPS-PQ-REQUIRED")`, which F8 has.
  - The resolver logic is moved into `restrict()`. It returns `None` (alert 49) when no offered scheme is both in the
    profile and signable by the key. The behaviour is unchanged, but it now has an explicit empty-intersection check.
  - `provider_for` is now `pub fn provider(profile)`. It is the one kx and suite table both builders use, and
    tls-subject's client uses it too.
- **aegis-tls `kx.rs`**
  - `from_fixed_keys_for_kat` is now `pub` under `cfg(all(any(test, feature = "kat"), not(feature = "cmvp")))`, so it
    is absent from cmvp builds. The two KAT tests are `cfg(not(feature = "cmvp"))` too.
  - Feature `order-mutant` swaps in a second `combine` that puts the ML-KEM secret first. The wire share layout is
    unchanged.
- **tls-subject**
  - Its mini X.509 writer gains ecdsa-with-SHA384 (1.2.840.10045.4.3.3) and id-ml-dsa-87 (2.16.840.1.101.3.4.3.19).
  - Credentials:

    | profile | credential |
    |---|---|
    | P-UNIVERSAL, P-BSI-ALT | ML-DSA-87 and ECDSA-P384; the first one that can sign an offered scheme is served |
    | P-CNSA | ML-DSA-87 only |
    | PQ-REQUIRED | ML-DSA-44 |
    | all others | ECDSA-P256 |

  - `describe` and `serve` work for every profile except FIPS-CMVP, which is Pending in the floor build.
- **tls-subject client mode:** `tls-subject client <PROFILE> <host:port>`.
  - It connects over TCP and does a TLS 1.3 handshake using `aegis_tls::profile::provider(profile)`.
  - It sends `ping\n`, expects the same bytes back, and prints `negotiated=0x....`.
  - Resumption and early data are off. It refuses FIPS (P-PQ6) and Pending profiles.
  - Certificate chain validation is off, but the CertificateVerify signature is checked, and only the profile's
    sigalgs are offered or accepted.
  - The mode is compiled out with feature `cmvp` (mode A).
  - The kx-interop oracle is not on main yet and its CLI was not documented, so this is the CLI from the unit brief.
