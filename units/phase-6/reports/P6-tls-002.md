# P6-tls-002 report (implementer, 2026-11-04, base main a3a870c)

Follow-up to P6-tls-001: tls-subject now implements the oracles/kx-interop subject contract.

## Built
- `subjects/tls-subject/src/main.rs`
  - `interop-server <PROFILE>`: one stdio TLS server connection. Its config is the same `aegis_tls::server_config`
    that `serve` builds, with the same F12 credentials. It prints `interop: handshake ok group=.. version=.. suite=..`,
    echoes application data, answers close_notify with close_notify, and exits 0. On a TLS error it writes the
    pending alert, prints `interop: error ..` and exits 1.
  - `interop-client <PROFILE> <CA_PEM> <NONCE>`: one stdio TLS client connection to `aegis.test`, configured by
    `aegis_tls::client_config(profile, roots)` (the product client builder) with roots = CA_PEM only. Chain and name
    are validated by WebPKI, with no verifier override. The ClientHello is written first. It sends `<NONCE>\n`,
    waits for the echo, prints `interop: echo=ok`, sends close_notify and exits 0.
  - P6-tls-001's TCP `client <PROFILE> <host:port>` mode is **removed**. It was strictly redundant: nothing calls it
    (no gate, oracle or script), and it used a custom verifier with chain validation off. interop-client covers the
    same thing through the real product path.
  - `cmvp` and `interop` together are a `compile_error!`, so a cmvp build can't quietly link a rustls client.
- `subjects/tls-subject/Cargo.toml`: `default = ["interop"]`, `interop = ["aegis-tls/tls-client"]`
  (integrator permission).
- `profiles/cmvp/build.sh`: a one-flag change, `--no-default-features` added to the cmvp `cargo build` flags. It
  applies to both packages. aegis-bin's default is `[]`, so only tls-subject changes: `interop`, and with it
  aegis-tls `tls-client`, is off in the cmvp build.

## Open / for the integrator
- **cmvp build is red, and the cause is not this unit.** `profiles/cmvp/build.sh` on kamrui ran with the new flag
  (`cargo build --locked --keep-going --no-default-features -p aegis-bin -p tls-subject --features aegis-bin/cmvp,tls-subject/cmvp --release`)
  and exited 101. The cause is ML-DSA APIs that the cmvp aws-lc-rs 1.15.3 lacks:
  - `aegis-audit`, `aegis-token`
  - tls-subject `PqdsaKeyPair`/`ML_DSA_*_SIGNING`, in P6-tls-001's credential code (lines 33/98/99/114)

  None of these are in code this unit touched. P6-cmvp-001's territory. The `interop`/`cmvp` guard did not fire, so
  the flag works.
- Feature unification: a single `cargo build`/`clippy`/`test --workspace` invocation now compiles aegis-tls with
  `tls-client` for every member, aegis-bin included. `cargo xtask budget` builds `-p aegis-bin` alone and so is
  unaffected, and the cmvp build is covered by `--no-default-features`. Anything that measures aegis-bin from a
  workspace-wide build would see it.
- Cleanup: on kamrui, `target/order-mutant` and `oracles/kx-interop/target` were deleted.
